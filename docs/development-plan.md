# PicTour 后续开发计划

## 项目定位

PicTour 的目标是把景区、园区、展馆、校园等场景中的纸质或图片导览图，变成可实时定位的本地化地图。用户导入地图图片后，通过校准比例尺、方向和当前位置，让设备 GPS 位置显示在自定义图片地图上。

当前仓库是可交互 Demo，已经具备地图导入、拖拽缩放、罗盘、比例尺、位置标记、GPS 监听、双语文案和使用指南。下一阶段目标是把 Demo 做成可稳定使用的 MVP，再迁移或复用到小程序版本。

## 本轮已修复的问题

1. GPS 参考点未绑定手动校准位置。
   - 旧逻辑在定位初始化时固定使用图片中心作为参考点，导致用户手动设置当前位置后，后续 GPS 投影仍可能偏移。
   - 新逻辑使用用户手动设置的位置作为 GPS 参考点，并用版本号触发重新锚定。

2. 图片坐标和屏幕坐标换算忽略 `object-contain` 缩放。
   - 旧逻辑直接把原图像素当作屏幕像素，图片被浏览器缩放后，用户标记会和视觉地图错位。
   - 新逻辑按容器尺寸和图片尺寸计算实际显示缩放，再进行坐标换算。

3. 上传图片缺少基础校验。
   - 新增 JPG、PNG、WebP MIME 限制和 15MB 文件大小限制。
   - 禁止直接导入 SVG 等风险更高的图片类型。

4. 比例尺输入缺少边界保护。
   - 新增比例尺归一化，避免空值、0、负数或非法数值造成定位换算 `NaN` / `Infinity`。

5. 构建配置隐藏错误。
   - 关闭 Next.js 构建时忽略 ESLint 和 TypeScript 错误的配置，让后续交付能暴露真实问题。

6. 基础安全头缺失。
   - 新增 `X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` 和 CSP。

7. 图表组件的内联样式注入缺少防护。
   - 对 CSS token 和 CSS value 做基础过滤，降低未来复用该组件时的样式注入风险。

8. 两点校准缺少产品流程。
   - 新增设置入口和中心图钉采集流程。
   - 用户在两个真实地点分别采集地图点和 GPS 后，系统自动计算地图方向与比例尺。

9. 地图和校准数据缺少本地持久化。
   - 新增 IndexedDB 本地存储，保存地图图片、图片尺寸、方向、比例尺和 GPS 参考点。
   - 新增缓存清理入口，可删除本地保存的地图和校准数据。

10. 隐私说明不够显性。
   - 新增首次打开隐私政策弹窗。
   - 顶部工具栏新增隐私政策按钮，强调所有地图、校准和定位计算都只发生在本地设备。

11. 定位可信度缺少反馈。
   - 新增定位状态条，显示定位中、定位异常、GPS 精度和更新时间。

## 仍需解决的核心缺口

1. 校准模型仍不够准确。
   - 当前模式依赖一个 GPS 参考点、手动方向和手动比例尺。
   - 图片自身像素和真实比例之间仍使用估算值，不能保证不同照片、不同裁剪、不同屏幕下的精度。

2. 两点校准已有基础流程，但还缺少质量反馈。
   - 当前流程会采集两个地图点和两个 GPS 点，并自动计算方向与比例尺。
   - 后续应显示两点距离、GPS 精度、计算后的比例尺置信度，并允许用户重采单个点。

3. 定位质量反馈已有基础版本，但还可以更精细。
   - 当前能显示 GPS 精度和更新时间。
   - 后续可增加精度圆、定位漂移提示、弱 GPS 环境建议。

4. 本地保存已有基础版本，但还缺少多地图管理。
   - 当前保存一个地图配置。
   - 后续可支持多个景区地图、命名、切换和导出分享包。

5. 缺少离线和小程序适配层。
   - Web 版依赖浏览器 Geolocation；小程序版本需要抽象定位、文件选择、缓存和权限 API。

## 推荐开发路线

### 阶段 1：稳定 MVP

目标：让用户在一个景区内完成导入、校准、定位、退出再进入仍可继续使用。

- 完善两点校准向导，增加重采点、距离提示和 GPS 精度反馈。
- 在地图上支持点选校准点，不只依赖中心图钉。
- 显示 GPS 精度圆、定位状态、上次更新时间。
- 对用户位置超出地图边界时给出提示，而不是静默飘出。
- 用 IndexedDB 持久化地图图片和校准配置。
- 增加“重置地图 / 重新校准 / 删除本地数据”功能。
- 为坐标换算、GPS 距离、方位角、两点校准增加单元测试。
- 用 Playwright mock geolocation 做端到端测试。

### 阶段 2：小程序版本

目标：把核心能力迁移到小程序，并保持定位和校准逻辑可复用。

- 抽出平台无关的 `calibration`、`geo`、`map-coordinate` 纯逻辑模块。
- 封装 Web / 小程序两套平台适配器：定位、文件选择、权限、存储。
- 小程序端优先支持拍照导入、相册导入、地图配置本地保存。
- 根据小程序定位 API 优化定位频率和电量消耗。

### 阶段 3：体验优化与创新

目标：降低校准门槛，让普通游客更快上手。

- 自动校准建议：用户走一段距离后，系统提示“是否用当前移动轨迹优化方向和比例尺”。
- 地标辅助校准：让用户在地图上标记入口、游客中心、卫生间等显著地标，提高修正体验。
- 多地图配置：支持一个景区保存多张地图，例如总览图、分区图、楼层图。
- 地图分享包：导出不含个人轨迹的地图图片和校准参数，方便同行用户复用。
- 隐私模式：默认不保存轨迹；如果未来做轨迹记录，必须本地加密并明确开关。

## 验收标准

- 用户能导入地图并完成两点校准。
- 在 GPS 精度较好的室外环境中，用户移动 10 米以上，地图标记方向和距离变化符合预期。
- 刷新页面后地图和校准配置仍可恢复。
- 构建、类型检查、lint、核心单元测试全部通过。
- 浏览器安全头存在，上传文件类型和大小受限。
- 所有定位和地图数据默认只保存在本地，不上传服务器。
